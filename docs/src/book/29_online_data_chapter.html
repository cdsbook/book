20  Online Data

ImportantWarning

This chapter is in an early draft form, and is incomplete.

The internet provides access to a huge amount of data that could be analyzed to study scientific questions.

Generally speaking, there are three main sources of datasets from the internet:

  1. Existing datasets that have been shared online
  2. Websites that provide access to data on request.
  3. Creating your own datasets from web pages.

As with everything you find on the internet, user discretion is needed to evaluate quality and trustworthiness.

20.1 Existing datasets

Many scientific (and non-scientific) datasets are provided online as files that can be downloaded.

The ease with which one can understand the contents of the dataset, and begin working with it, varies, often based on how much effort the dataset’s creator put into making it reuseable by others.

Here are some places to look for datasets:

  • R packages: Many R packages include datasets. These datasets are usually relatively small (to keep the package small), and the contents are usually tabular.

    One nice feature of most of these datasets is that the package’s creators usually put effort into making the datasets re-usable. The data has often been cleaned, and the package documentation will come with a help page describing the dataset.

    • The datasets package contains (unsurprisingly) many datasets! It is one of the default packages installed as part of the R programming language itself. Since this means that every R user has access to it, these datasets are frequently used in R example code, leading to a kind of infamy for some of these datasets (such as the iris dataset).

    The data() function returns a list of datasets in any package that you have already installed. Running data() without arguments will typically just show datasets in the datasets package.

    To see datasets from a particular package, pass that name to the package argument, e.g.

    data(package = "ggplot2")

    The package argument can accept a vector of multiple packages (e.g. package = c("ggplot2", "dplyr")), which means that the following code will list all of the datasets in every package installed in your system:

    data(package = .packages(all.available = TRUE))

  • Many websites exist with the goal of sharing datasets for data science. The quality of these websites varies, as does the quality of the data within each dataset.

    Some examples:

    • Kaggle runs data science competitions, but also hosts datasets uploaded by its users at kaggle.com/datasets.

      The datasets are easy to search and browse, and cover a wide range of topics. You can also see code and analyses of each dataset that have been shared by other Kaggle users.

      Unfortunately, since anyone can upload a dataset, the quality is patchy. In particular, you should be careful about the source of the data - many datasets just contain simulated data rather than real observations.

    • The UC Irvine Machine Learning Repository is a curated list of datasets focused on predictive tasks. The data is often high quality, with a well defined provenance.

      The datasets are currently hosted at archive.ics.uci.edu

20.2 Requesting data through APIs

In many cases, an organization or website will provide an alternative method to access its data: an API, which stands for Application Programming Interface.

The term “API” has a few different uses in programming, but in general it refers to a defined way to access another computer program which should return a defined result.

In the context of internet data, it refers to ways of writing web addresses (or URLs (Uniform Resource Locators)) to tell a website to return a particular set of data.

20.2.1 Building a web address

A basic web address, e.g. https://cran.r-project.org/ has a few parts:

  1. https:// is the protocol that your computer will use to contact the website. HTTPS stands for Hypertext Transfer Protocol Secure, which is the typical way of browsing the internet securely (i.e. encrypting your data).

  2. cran.r-project.org is the domain of the website. Other examples are www.google.com or www.gmu.edu

We can specify particular webpages of a website by putting a path after the domain:

https://cran.r-project.org/web/packages/index.html

20.2.2 APIs

Websites with APIs will define certain URLs that are called endpoints. An endpoint can be used to access a particular type of data.

URLs can also contain queries. These are typically used to customize the webpage in some way. They go at the end of the URL, after a ?. In APIs, queries are often used to specifiy the particular data we want.

For example:

https://www.some-website.com/api/endpoint-3/?year=2010&format=json

  • https://www.some-website.com/api/global-temperatures/ is the API endpoint.

  • year=2010&format=json is the query that contains two parameters: year=2010 and format=json

    • year and format are examples of parameter names.

    • 2010 and json are the corresponding parameter values.

Most APIs will come with documentation that describes the available endpoints, as well as the parameters that can be used to customize each endpoint’s response.

20.2.3 The Paleobiology Database API

The Paleobiology Database (PDB) is a research project that digitizes information about fossils from published research (such as where a fossil was found, or how old it is). This data is then available for anyone to access and use.

PDB provides an API to access this data, which is currently documented at: paleobiodb.org/data1.2/

One of the endpoints returns information about when and where a particular fossil occurs. This endpoint is /data1.2/occs/single.json and an example of a response is:

https://paleobiodb.org/data1.2/occs/single.json?id=139292&vocab=pbdb
{
  "elapsed_time":0.00145,
  "records": [
    {
      "occurrence_no": "139292",
      "record_type": "occ",
      "reid_no": "22878",
      "collection_no": "11917",
      "identified_name": "Tyrannosaurus rex",
      "identified_rank": "species",
      "accepted_name": "Tyrannosaurus rex",
      "accepted_rank": "species",
      "accepted_no": "54833",
      "early_interval": "Late Maastrichtian",
      "max_ma": 72.2,
      "min_ma": 66,
      "reference_no": "4218"
    }
  ]
}
  • This particular request contains two parameters:
    • id=139292 which specifies the particular occurrence that we are requesting
    • vocab=pbdb which tells this particular API that we do not want the API to include certain abbreviations.
  • This response is in a format called JSON, which is commonly used in APIs. JSON is made up of objects, which are created with curly brackets { ... }, and typically contain key: value pairs. You can think of the key as the ID for a piece of information (kind of like a column name) and the value as the data itself.
    • You might note that this has certain similarities to an R list - hold that thought, because it will be relevant shortly!

You should be able to copy and paste the the URL of this API call into your web browser and access the same data, although you will probably find that the response JSON is compressed into a single line of text that is much harder to read. This is because JSON is designed to be requested and processed by computer programs.

So how can we write an R program to retrieve that same API data?

20.2.4 API requests in R

There are many R packages that can be used to request webpages, but we will use one called httr2 (pronounced “hitter two”).

We could request the same API endpoint using the request() and req_perform() functions from the httr2 package:

library(httr2)

api_request <- request("https://paleobiodb.org/data1.2/occs/single.json?id=139292&vocab=pbdb")

api_response <- req_perform(api_request)

We have stored the response in api_response - printing out the contents of that variable shows:

api_response
<httr2_response>
GET https://paleobiodb.org/data1.2/occs/single.json?id=139292&vocab=pbdb
Status: 200 OK
Content-Type: application/json
Body: In memory (368 bytes)

One thing to note is the line that says Status: 200 OK, which means that the server was able to return the web page that we asked for. There are other codes that can be returned, such as the 404 code that you may have encountered when browsing the internet - that would mean that we requested a webpage that could not be returned.

resp_body_string(api_response)

The JSON object has been converted into an R list. Lists are a relatively natural way to store JSON-formatted data in R.

However lists aren’t necessarily ideal for analyzing data - in many cases we might prefer to convert this data to a data frame.

20.2.5 Converting JSON to data frames

This API response contains two fields at the top level:

  • elapsed_time, which tells us how long the server took to process our request, and which we can ignore.

  • records, which contains the information about this fossil occurrence. This is the part we care about.

    • It contains another list, which itself contains a list.

    • That inner-most list contains the key : value pairs of information that we need.

      • We could convert this list to a data frame, with the keys as column names, and the values as the data in a single row.

We can coerce the records item into a list using the as.data.frame() function

as.data.frame(
  json_response$records
)
  occurrence_no record_type reid_no collection_no   identified_name
1        139292         occ   22878         11917 Tyrannosaurus rex
  identified_rank     accepted_name accepted_rank accepted_no
1         species Tyrannosaurus rex       species       54833
      early_interval max_ma min_ma reference_no
1 Late Maastrichtian   72.2     66         4218

20.2.6 APIs with dedicated packages

Some very popular APIs may have packages dedicated to accessing their data. This simplifies the process immensely. Rather than writing code yourself to make the request and parse the response, you can just use an existing code which will often do most of the hard work for you.

Some examples:

  • The paleobioDB package can retrieve data from the Paleobiology Database API. For example:

    • pbdb_occurrence(id = 139292, vocab = "pbdb") would return the same 1-row data frame that we just retrieved by hand.

  • The tidycensus package fetches data from the US Census Bureau.

  • The uisapi package fetches data from UNESCO’s stats APIs.
