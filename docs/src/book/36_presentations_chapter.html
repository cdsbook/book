23.1 Making Presentations

It’s hard for me to imagine that anyone reading this book hasn’t sat through a slide presentation in their life, and very probably created their own.

Slide decks are commonly created with tools like Microsoft PowerPoint or Google Slides, but these are not the only options. One alternative is to render a slide deck from an RMarkdown or Quarto file. The slides for all of the videos in this book were created in this way!

There are advantages to this, particularly around reproducibility, since you can include the code that generates results/figures as part of the file, reducing the chance that you’ll forget to copy over the latest version of your graph onto slide 7. It’s also a less error prone way to include code examples (since you won’t be able to render the slides if you have an error in your code), and you can do cool things like include interactive code boxes that you can edit and run during the presentation!

A disadvantage (or, at least, a pitfall) is that it can take longer to setup and edit the slide deck, since you may have to fiddle with the formatting in the source file, and repeatedly re-render and tweak until you get the output looking how you want. By contrast, you can can often drag things around in a Powerpoint relatively quickly, and edit appearance with the click of a button.

As with many things in both computers and life, you get more power and flexibility but accept that it comes with greater risks and time commitment.

23.1.1 Presentation output files

PowerPoint presentations are stored in a dedicated file type, which has the extension .pptx. Since this was developed by Microsoft, there’s a non-proprietary that is sometimes used instead, which has the extension .odp.

It’s possible to render a R/Qmd presentation to a PowerPoint file, but doing so often limits the utility of making a presentation in this way in the first place.

Instead, it’s more common to render a presentation to an HTML file, i.e. a webpage!1

This means that you don’t need any special software to present such a rendered slide deck. You can just open the slides in the web browser of your choice, and you’re off.

In this chapter we will focus on rendering HTML slide decks. These will rely on another programming language, called Javascript, which is widely used to make web pages interactive.

Fortunately we don’t need to learn any Javascript ourselves! There are several R packages which will automatically render RMarkdown files to HTML-based presentations, and Quarto files can be rendered without needing any other packages.

The key idea behind most of these methods is that Markdown headings (e.g. line beginning with # or ##) are used to indicate new slides in the output file, instead of section headings.

Since the process differs, we will look at how to create a simple RevealJS presentation from both RMarkdown and Quarto files. We will then go over some basics of good presentations, before looking at how to add useful features in each type of source file.

23.2 Presentations with RMarkdown

There are several ways to turning RMarkdown files into presentations. We are going to focus on the revealjs package, but there are many similar options, which create slide decks with different styles and features.

You can see some of the different options in the examples below.

  • RevealJS

The revealjs package is a relatively new entrant to the space. It is not necessarily the best or most feature rich option (this author is partial to the xaringen package), but it creates slide decks using the reveal.js Javascript library which is also used by Quarto, which makes for a nice comparison between the two.

To indicate that an RMarkdown file should be rendered to a reveal.js presentation, you will need to set the output option in your header section (you will also need to install the revealjs package if it is not installed):

rmarkdown_presentation.Rmd
---
output: revealjs::revealjs_presentation
---
  • Source RMarkdown
  • Example Presentation
---
title: "Example Presentation"
author: "Your Name Here!"
date: "`r Sys.Date()`"
output: revealjs::revealjs_presentation
---


# First Slide

::: incremental

* Bullet 1

* Bullet 2

:::

# Another Slide

```{r, warning=FALSE, message=FALSE, echo=FALSE}
ggplot2::qplot(x = Sepal.Length, data = iris)
```

In general, the basics of what you can do with just the revealjs package are somewhat limited - it has everything you need (and at least one thing you probably don’t) to create a deck of slides, but more advanced customizations will need other R packages.

We will discuss some of these features you can add to an RMarkdown reveal.js presentation later in this chapter, after we look at how we can create the same basic presentation from a Quarto file.

23.3 Presentations with Quarto

Quarto files can be rendered directly to reveal.js presentations without needing any extra R packages.

To do so, just change the output file format option in the header section:

quarto_presentation.qmd
---
format: revealjs
---
  • Source Quarto
  • Example Presentation
quarto.qmd
---
title: "Example Presentation"
author: "Your Name Here!"
date: "`r Sys.Date()`"
format: revealjs
---


## First Slide

::: {.incremental}

* Bullet 1

* Bullet 2

:::

## Another Slide

```{r}
#| warning: false
#| message: false
#| echo: false
ggplot2::qplot(x = Sepal.Length, data = iris)
```

Because Quarto contains a lot of features for presentations built into the rendering engine, you can add a lot of features to your slides without needing extra packages or extensions (compared to RMarkdown). The downside of this is that it can be harder to do something beyond this, since there is not the same ecosystem of packages and extensions for customizing slides.

23.4 Designing Slides

23.4.1 Slides and Sections

Most Markdown formatting symbols are treated normally, as introduced in Section 4.3.

The one Markdown difference to remember is that headings are used to create slides (rather than sections). By default:

  • Second level headings (e.g. ##) are used to indicate new slides. The heading text will become the slide title.
    • To create a slide without a title, use a line of three dashes: ---
  • Level 1 headings (a single #) create a new section within the slide deck.

RMarkdown+reveal.js slides have an unusual 2-D layout of sections and slides. The slide deck will be laid out in a grid, where each section creates a new column (i.e. section slides are added horizontally), and regular slides are added below their section (i.e. vertically). This means that when navigating through the slides, you need to remember whether to move down or right to get to the next slide in the sequence. This makes it very easy to forget about slides (at least in this author’s experience). Fortunately you can turn this behavior off by setting the navigation mode to linear in the header options, which will stack all the slides one after another:

rmarkdown_example.Rmd
---
output:
  revealjs::revealjs_presentation:
    reveal_options:
      navigationMode: linear
---

23.4.2 Columns

Columns can be created using the block syntax (a line of three or more colons, e.g. :::, opening and closing the block).

:::: {.columns}

::: {.column width="50%"}

Contents of first column.

:::

::: {.column width="50%"}

Contents of second column.

:::

::::

Note:

  • We can assign attributes to the blocks using curly brackets after the opening colons.

    • For columns, we need a parent .columns block that contains all the columns, within which we have a .column block for each column.

    • We can use the width attribute to customize the widths of each column.

  • To nest blocks, parent blocks need more colons than their children, e.g. the .columns container block is created with four colons instead of three.

23.4.3 Incrementally revealing items

It can be overwhelming for an audience to see a slide of lots of text. To reduce the cognitive overload, we can reveal the content on a slide piece-by-piece rather than all at once.

Since this is commonly done with lists (bullets or numbered), there is an incremental block that we can put around a list:

::: {.incremental}

* First point

* Second point

:::

We can also customize the placement breaks within slides, using a line of three dots (with spaces between them):

## Slide Title

First point

. . .

Second point

23.4.4 Slide backgrounds

We can include images using the standard Markdown formatting described in Section 4.7, in which case the image will typically be scaled to fit into the content area of the slide (i.e. within the same margins as the text).

However, it is often more visually interesting when an image occupies an entire slide (with no margins). We can do this by setting a background image for a slide:

## {background-image="https://images.unsplash.com/photo-1464802686167-b939a6910659"}

In this case we are creating a new slide with a level 2 heading ## and then adding the background-image attribute inside curly brackets. The image can be a file on your computer or, as in the example above, the URL of a file on the internet.

As the word “background” in “background image” implies, you can add content to a slide over it. You should be careful doing so, since it can overload the information content on the slide, but if you do so then you should also consider setting the background-color attribute of the slide. The background color won’t be visible (since it’s behind the image), but it will cause the font color of the slide contents to change from black to a color that contrasts with the background.

For example, setting the background color to black changes the font color to white:

## Background Images {background-color="black" background-image="https://images.unsplash.com/photo-1464802686167-b939a6910659"}

Adjust `background-color` to get a contrasting font color.

You can also omit the image to get slides with a non-white background:

## Background Color {background-color="black"}

A non-white slide with a contrasting font.

23.4.5 Presentation themes

Of course, tweaking colors slide by slide can become arduous, especially if you want to adjust the color of every slide!

reveal.js comes with several pre-existing themes (see the full list here) than can be used change the appearance of every slide. These can be set in the header section of the source file.

  • RMarkdown
  • Quarto
output:
  revealjs::revealjs_presentation:
    theme: dracula
---
format:
  revealjs: 
    theme: dracula
---

Pretty much every aspect of the slide styling can be customized if you wish to do so - resources are provided at the end of this chapter.

23.4.6 Code chunks in slides

A big reason for creating slides in RMarkdown or Quarto is that it allows us to do literate programming: we can include code, and its output, as part of the course document. No more having to copy your graphs from a separate software program into a PowerPoint presentation!

The code chunks in Quarto presentations have a few defaults settings that are different to other output types (and to RMarkdown presentations):

  • Code chunks are hidden by default. You can override this either in the heading options, or in the options for an individual code chunk. (Code can easily overwhelm an audience, hence the choice to hide it - you usually only need to show it if you are trying to discuss or teach some aspect of the code itself.)

  • If a code chunk is echoed, then line numbers are shown next to the code.

Since code can be overwhelming for an audience to follow in a presentation, it is a good idea to design slides to emphasize code you wish to focus on. There are different options depending on whether you are working in R Markdown or Quarto.

23.4.6.1 RMarkdown line numbers

You can turn on line numbers for a code chunk by:

  1. Adding a CSS code chunk somewhere2 in your source file (CSS is the language used to format webpages, including reveal.js presentations):
<!-- Somewhere in your file -->

::: {.cell}
<style type="text/css">
.reveal pre code {
  overflow: visible;
}
</style>
:::
  1. Setting the attr.source option of the code chunk as follows:

::: {.cell}

```{.r .cell-code .numberLines}
iris |>
  ggplot() +
  geom_point(aes(Sepal.Length, Sepal.Width))
```

::: {.cell-output-display}
![](36_presentations_chapter_files/figure-html/unnamed-chunk-4-1.png){width=672}
:::
:::

23.4.6.2 RMarkdown code highlighting

RMarkdown code chunks can be highlighted using the flair package. Its usage is described in the package’s documentation.

23.4.6.3 Quarto line highlighting

In a Quarto file we can highlight lines using the code-line-numbers option:


::: {.cell}

```{.r .cell-code  code-line-numbers="3,5-6"}
iris |>
  ggplot() +
  geom_point(
    mapping = aes(
      x = Sepal.Length,
      y = Sepal.Width
    )
  )
```

::: {.cell-output-display}
![](36_presentations_chapter_files/figure-html/unnamed-chunk-5-1.png){width=672}
:::
:::

What this actually does is de-emphazise the other lines.

23.4.6.4 Quarto code highlighting

Unfortunately the flair package does not work with Quarto source files.

We can use a Quarto extension called detective, but it is not as powerful as the flair package.

---
format: revealjs
revealjs-plugins:
  - detective
---

## Example Slide

::: {.detective data-detective-search="plot"}

```{.r}
qplot(x = Sepal.Length, data = iris)
```

:::
